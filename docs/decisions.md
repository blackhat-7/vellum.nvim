# Decisions

Why things are the way they are: read before undoing something. One entry per choice, one to three lines; when a choice changes, rewrite its entry.

- **Preview is a real buffer, rendered in Lua.** (2026-09-22) No external process for text: tree-sitter's bundled markdown parsers are fast and always there. Extmarks carry all styling.
- **Mermaid runs in a real headless browser, not a fake DOM.** (2026-09-22) happy-dom + resvg (tried first, from mdtui) mis-measures text: flowcharts overlap and class/gantt diagrams fail. Puppeteer's `chrome-headless-shell` renders exactly like GitHub. One process stays alive; PNGs are cached on disk by hash of theme + code.
- **Images use kitty Unicode placeholders.** (2026-09-22) The image is sent once; the buffer holds placeholder text colored with the image id. It scrolls, clips and works in tmux with no redraw code. Requires kitty or Ghostty; elsewhere diagrams show as code.
- **PNG bytes are sent inline, in 4 KB chunks, never as a file path (`t=f`).** (2026-09-23) Over ssh + tmux the terminal is on another machine and cannot read our cache; images silently never appeared.
- **Under tmux, check the client has RGB before showing images.** (2026-09-23) The placeholder's 24-bit color is the image id; tmux downgrades it to 256 colors unless `terminal-features` says RGB (ssh drops `COLORTERM`). The diagram panel then says the exact tmux.conf line.
- **Wide tables scroll sideways rather than shrink past readable.** (2026-09-23) Found by sweeping real files: a 19-column table split words mid-word. Tables stop shrinking at their longest word.
- **Low-contrast node labels are recolored.** (2026-09-23) `classDef` fills written for GitHub's light page leave light-on-light text on a dark theme; labels under 3:1 contrast switch to dark or light ink.
- **Colors derive from the active colorscheme.** (2026-09-22) Headings use Function/Statement/String/Type/Constant/Special colors; tints are blends toward Normal bg. Diagrams get matching mermaid themeVariables.
- **Blocks, heading sections included, are cached by (type, width, depth, MDX, source text).** (2026-09-22, sections 2026-11-07) A keystroke re-renders only the blocks around the edit: 2.3 ms on 5,000 lines, 7 ms when sections were rebuilt each time. Output that shows a render still pending (`browser.waiting`) is never cached. An `.mdx` section hides MDX lines, hence MDX in the key.
- **Requires Neovim 0.12.** (2026-09-22) `nvim_ui_send` is the clean way to send graphics escapes from the server; no compatibility layer for older versions.
- **Diagram size targets terminal text size.** (2026-09-22) Scale = cell height / 24 per CSS px, so 16px diagram text lands near the terminal font. Capped at the content width.
- **Highlights go through a decoration provider, not stored extmarks.** (2026-09-22) Setting 15k extmarks per keystroke cost 9.6 ms on a 5,000-line doc; ephemeral marks on drawn lines cost nothing. Flattened lines are memoized on the cached line tables (`line.flat`).
- **Remote images are fetched by the headless browser and re-fetched daily.** (2026-09-23) GitHub shows them too; badges and screenshots are common in READMEs. The cache key is URL + date; local files key on mtime + size.
- **Gantt defaults differ from GitHub: `axisFormat: '%b %d'`, 15px labels.** (2026-09-22) Gantt fills the 800px viewport, then scales down to the pane; GitHub's full dates overlapped. A diagram's own `axisFormat` still wins.
- **Images inside text: one row high inline, else their own lines.** (2026-09-23) An image up to ~1.5 text rows tall (badges, icons) becomes one placeholder row in the line; a bigger one breaks the line and shows as a block. In table cells big images keep alt text: a block would burst the cell.
- **Images are screenshotted bare; only diagrams get padding.** (2026-09-23) The 12px diagram padding made a 20px badge 44px tall, too tall to sit in a line.
- **The renderer starts on the first uncached picture and stops after five minutes idle.** (2026-11-08) It used to start when `:Vellum` opened and run until Neovim quit, holding 100-200 MB of Chrome all session. The first render comes right after open anyway, so starting on demand costs nothing there; after an idle stop, the next new picture waits ~0.6 s more.
- **Render loaders show only once a wait is noticeable.** (2026-11-08) A spinner that flashed for a 0.2 s render looked broken. A new diagram shows its code, with a spinner after 0.4 s; an edited one keeps its old picture, with an 'updating' badge after 1 s.
- **The PNG cache is capped at 100 MB, pruned once per session.** (2026-09-23) Oldest mtime goes first; using a file bumps its mtime, so this is least-recently-used. Pruning runs when `browser.lua` loads, before any file is shown, so nothing on screen is deleted.
- **Images shrink to fit the pane.** (2026-09-23) An overflowing diagram showed only its left edge, usually empty, so a narrow pane looked blank; scroll sync resets sideways scrolling, so the overflow could not be read anyway. (It replaced a 75% floor that let wide diagrams scroll sideways.)
- **An image's pixels are sent once per file; a resize only re-places it.** (2026-09-23) The id used to include the size, so each resize re-sent the whole PNG under a new id. Under tmux it often never showed. A new size is now a tiny delete-and-place command.
- **The preview redraws 80 ms after a resize settles, not on every column.** (2026-09-23) Drag-resizing re-rendered everything and re-placed every image per column: 4x nvim CPU, and the drag lagged. Now CPU during a drag matches plain nvim.
- **Queued renders the document no longer needs are cancelled.** (2026-09-23) Typing in a diagram queued a render per keystroke; a large one showed its final version 3.6 s late. After each draw, pending renders not requested by it get `{"cancel": out}`; now 0.34 s.
- **The theme signature is JSON with sorted keys.** (2026-09-23) It is part of every diagram's disk cache key. Unsorted, Lua table order changed per session, so every session re-rendered every diagram and the cache filled with duplicates.
- **The README demo is an animated WebP.** (2026-09-23) GitHub plays video inline only from its own upload URLs; a GIF of the long demo was 10–16 MB, WebP is 5.6 MB at 1200 px, 20 fps.
- **Inline math is Unicode text; display math is a KaTeX image.** (2026-09-23) Text keeps line height, needs no terminal graphics and is instant; `latex.lua` converts common LaTeX and shows unknown commands as written. Display math uses the same renderer as mermaid. KaTeX is already a mermaid dependency; now listed directly.
- **`$…$` is math only when it hugs its content and no digit follows (Pandoc's rule).** (2026-09-23) Tree-sitter pairs any two dollars, so "$5 and $10" lost its dollar signs.
- **The renderer page is in standards mode.** (2026-09-23) KaTeX refuses quirks mode. Mermaid SVGs are made blocks so diagrams stay pixel-identical (checked on `test/diagrams.md`).
- **Only a row's first placeholder cell carries diacritics.** (2026-09-23) Kitty gives bare cells the next column. Full marks doubled redraw bytes (41 → 21 KB per scroll step on the demo doc), which lagged over ssh.
- **The image viewer crops by placeholder cells, under its own image id.** (2026-09-23) Kitty ignores source rectangles on virtual placements (tested in 0.48). Zoom re-places the image; pan only rewrites text. Its own id keeps the preview's placement untouched. Zoom caps at 297 cells a side, about the PNG's own resolution.
- **Placements carry a fixed placement id (`p=1`); re-placing replaces in one command.** (2026-09-23) Replaces the delete-then-place pair: half the bytes and no moment without a placement.
- **The preview closes with its source.** (2026-09-23) Once no window shows the source (`:q`, `:bd`, `:e` of a non-markdown file), the preview had nothing to follow, and an unloaded source rendered empty. Another markdown buffer in that window still takes the preview over.
- **`[[x]]` is an Obsidian wikilink, shown as the link "x".** (2026-09-24) GitHub shows `[[x]]` literally, but it is rare there and everywhere in Obsidian notes. Callout text on the `[!type]` line is a title (Obsidian); GitHub alerts are unchanged.
- **Export uses `marked` + `marked-footnote` in the renderer, with our own math rule.** (2026-09-24) The preview draws terminal lines, not HTML, so export needs a markdown→HTML step; both have no dependencies. `marked-katex-extension` was dropped: it either missed `$x$` at a line start or made "$5 and $10" math. They load on first export, so an old build still draws diagrams.
- **Tab preview: `tabnew`, then the preview buffer replaces its sole window.** (2026-11-02) The tab then holds only the preview, so closing the preview (`q`, `:q`) closes the tab, and `bufhidden=wipe` takes the buffer with it. `nvim_open_win` has no new-tab split. `tab = true` asks to see the preview, so `:Vellum` switches to its tab (`gT` brings the source back); the first draw syncs through the source window, wherever the focus is.
- **Tab/S-Tab/gt move tab pages in the plugin's two windows in tab mode.** (2026-11-02) Tab mode puts the focus where the user's Tab-key muscle lives, and buffer cycling errors in the pinned preview window; the preview buffer and the previewed markdown buffer carry these keys while the preview is open, their own bindings return on close.
- **Placements re-send when the preview window becomes visible.** (2026-11-02) Tabbing away overwrites the screen and kitty placements do not re-anchor to text reprinted on the way back (the zoom viewer's 100 ms pattern), so BufEnter on the preview re-places every image on screen once its redraw has settled.
- **Nix packages its own browser and names it in `render/.puppeteerrc.cjs`.** (2026-11-07) Puppeteer only downloads at install, which the Nix sandbox forbids. Linux uses nixpkgs chromium (Chrome for Testing has no aarch64-linux build); macOS a pinned headless shell. The renderer runs in `render/` so that config is found and a user's project config is not.
- **The nixvim module sets no keymaps.** (2026-11-07) nixvim joins `keymaps` lists, so an importer could not remove a default one; the README shows one to copy.
- **`:Vellum build` installs the renderer; replaces the `:Lazy build vellum.nvim` hint.** (2026-09-24) The lazy-only command left users of other managers (and the README's manual path) with a long `:lua` line. It opens a terminal so npm and the Chrome download are visible. It and root `build.lua` share the command list in `lua/vellum/build.lua`.
- **MDX `import`/`export` lines and `{/* comments */}` are hidden.** (2026-10-07, preview 2026-11-07) They are code and comments, not content, like HTML comments. Only top-level paragraphs count, as in MDX. The preview skips their blocks in the walk (re-parsing a blanked copy cost 31 ms per keystroke vs 8); export blanks the lines. A file is MDX by `.mdx` name or an `mdx` filetype part.
- **`max_pixels` caps a PNG by lowering its scale; the scale is stored in the PNG's pHYs chunk.** (2026-10-23) herdr drops kitty images above about 5.9 MP without a word, and big flowcharts at 2x reach 14–20 MP. The renderer picks the scale per shot and writes it as pHYs, so a cached PNG still shows at its CSS size after a restart. The CRC is computed by hand: `zlib.crc32` needs Node 22.2.
- **D2 has a bundled renderer: `@terrastruct/d2` (WebAssembly) in node.** (2026-11-07) Nothing to install beyond the renderer: ~40 ms a diagram, loaded on the first D2 block (~0.4 s). 57 MB, no dependencies, MPL-2.0. Asked for in issue #2.
- **D2 colors: base theme 200 (dark) or 0 (light) by the colorscheme's lightness, every theme color overridden.** (2026-11-07) The base only picks code-label syntax colors; a light base put white code boxes on a dark preview. A diagram's own `theme-id`/`theme-overrides` wins; `theme-id: 0` cannot be told from none, so it gets ours.
- **Local D2 icons go in as data URLs, resolved in the markdown file's folder.** (2026-11-07) The page is about:blank and cannot read files. Their mtime and size join the cache key, found by scanning `icon:` values in Lua, as local images are keyed in `media.lua`.
- **The renderer's Chrome runs with `--font-render-hinting=none`.** (2026-11-07) On Linux, hinting rounds glyph advances to whole pixels (9.6 → 10 px), so text came out wider than D2 laid it out and code overflowed its boxes. Without hinting, Linux and macOS give the same widths.
- **D2 pads itself (12 px, its `pad`), and the shot is the SVG alone.** (2026-11-07) At `pad: 0`, shapes on the diagram's edge lost the outer half of their border. The margin matches mermaid's 12 px from `#c`.
- **The user's `d2` command renders D2 when installed; the bundled one otherwise.** (2026-11-07) It is newer (v0.9 vs v0.7) and runs their layout plugins (TALA). Its flags override a diagram's `d2-config`, so our padding and colors go in as `d2-config` appended to the source, only for keys the diagram leaves unset, read with the bundled compiler. Its version is part of the cache key.
- **`Vellum*` highlight groups are set with `default = true`.** (2026-11-07) Users could not restyle the preview: every apply overwrote their groups. `:colorscheme` clears all groups first, so derived colors still follow a new scheme. The plugin's ColorScheme handler is scheduled after users' handlers, so merged groups copy their colors.
- **`setup()` warns about unknown and mistyped options and keeps the defaults for them.** (2026-11-07) A typo did nothing without a word. `tab` stays a boolean beside `split`, so v0.3 configs keep working.
- **`auto_open` opens on BufWinEnter of markdown in a normal file window.** (2026-11-07) Hover popups and picker previews are markdown too; `buftype` and floating windows rule them out.
- **Local image paths are read as URLs: `file://` URIs and `%XX` escapes are decoded.** (2026-11-09) Link destinations are URLs, and tools like img-clip write `file:///…/my%20shot.png`; such images showed nothing. The path as written is tried first, so a file whose name really holds `%20` still loads.
